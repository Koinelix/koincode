# Koinelix image generation

This is an independent image client. Its Python scripts own the service HTTP, business parameters, stable requests, recovery and image handling. A general wallet is called only after a real 402. The wallet does not configure this service or decode its images. Never put an API key, payment signature or full Base64 image in chat, prompts, logs or tool arguments. Installing this Skill grants no payment authority.

## Host and API selection

KoinCode remains the default host and uses its generic `wallet_run_client` tool and private fd 3. A separate trusted POSIX host may instead use the [reference adapter](references/reference-host.md), without starting KoinCode. Select only a host actually configured by the user; never use a shell workaround when KoinCode denies or lacks a capability.

New image requests default to anonymous x402 wallet payment. No service API key is needed: the client omits Authorization and calls the wallet only after an actual 402. A prompt-only request is valid on the current platform; omitting model uses the server's configured default model. If the user names a published model, pass `--model <id>` and use exactly that model. Do not invent a model ID or require the user to select one for an ordinary request.

The client freezes the original body and mode before HTTP. An existing operation, including an old credentialed request, keeps its saved mode on recovery; never turn an authentication failure into an anonymous retry. Explicit `--access-mode credentialed` and `--api-version legacy-v1` remain compatibility options for existing callers; they are not the normal generation path. See [API modes](references/images-api.md).

## Generate an image

For an ordinary request, use the following two steps in order:

1. **Before calling the wallet tool**, resolve `scripts/generate_image.py` relative to this loaded SKILL.md to its canonical absolute path. Resolve this one path even if it appears absolute: its parent directories may be symlinks. For example, run `python3 -c 'import pathlib, sys; print(pathlib.Path(sys.argv[1]).resolve(strict=True))' "<loaded-skill-directory>/scripts/generate_image.py"` with the actual loaded directory as the argument. If resolution fails, stop and report the path error.
2. Call `mcp__koincode_wallet__wallet_run_client` once with `runtime: "python3"`, the resolved path as `script`, and `args: ["--prompt", "<user's image description>"]`. This uses the server's default image model and anonymous wallet payment without an API key. Append `["--model", "<published model id>"]` only when the user selected that model. Preserve the user's image description without adding invented details. The script reads its configured endpoint itself. If the tool is absent, report the missing host capability; ordinary Bash/Python cannot replace its private connection.

If the user sets a per-payment spending ceiling, pass the host tool's `paymentLimit` with the actual network, asset address and integer `maxAmountAtomic`. For Base Sepolia USDC, 0.1 USDC is 100000 atomic units. This is a stricter per-invocation ceiling enforced by the host, independent of the wallet's global limits. Do not change global wallet limits or stop merely because they are higher. A quote outside this ceiling is rejected before approval or signing.

Do not search directories, environment variables, local configuration, source code or wallet data to discover an endpoint or parameters.

The current text-to-image API accepts prompt and optional model. Do not pass legacy size, quality or output-format flags on the default path; see [image API](references/images-api.md). Those flags remain only for an explicitly selected legacy API on a compatible service. Python 3.9+ is required. The script decodes Base64 with the Python standard library and checks the image signature; it does not fully decode image pixels.

1. The client owns merchant HTTP and uses the wallet only for an actual 402. Do not call legacy `x402_request`, send raw business JSON to the wallet or load the scripts into the model context. Other compatible hosts can use the same client protocol; see [wallet compatibility](references/wallet-compatibility.md).
2. The default anonymous request does not read a service credential. Only an explicitly credentialed compatibility caller obtains its service credential through its separately configured provider. KoinCode optionally supplies an exact-target private credential service; it is outside the wallet. Other hosts may adapt that provider. The model never reads the credential. If it is unavailable, show the actual setup diagnostic instead of searching wallet files, Keychain or application code.
3. The script saves its business request and idempotency key before HTTP. On an actual 402, it uses the general payment protocol. The wallet validates the submitted challenge, client scope and limits. KoinCode preserves the wallet's existing authorization policy: a valid matching grant and unlocked wallet can pay automatically within wallet limits and any lower invocation ceiling. Missing authorization or a locked wallet follows the existing trusted confirmation/unlock flow. Do not require another prompt solely because this is a Skill, create broader grants or change limits. The user completes any required system authentication. External hosts apply their configured payment protocol. This does not independently prove the HTTP response's origin. The script receives consumable payment material through its private connection, submits the same original request, and never exposes that material to the model. A 401/403 does not request payment.
4. The script saves the complete response before decoding and publishes a bounded validated image file. The generic host tool returns `artifacts` with session-owned URIs. Display each image using Markdown image syntax with its returned URI; put the exact returned URI in the Markdown image target. Do not print Base64, open raw response files, or request another generation for a preview failure. Do not automatically upload the result to a vision model or another service.
5. For an uncertain result, preserve `operationId` and `paymentId`. Use the same script with `args: ["--recover", "<original-operationId>"]` in the original session to re-deliver an already saved response; it uses the original saved endpoint even if configuration changed. This path does not send merchant HTTP or sign again. If no response is retained, it reports pending. The client does not implement the merchant's advanced quote-replacement or new-attempt flows described in [x402 and recovery](references/x402-and-recovery.md).

For an ordinary successful new generation, lead with the image and a short result message. Show the exact `--prompt` argument sent to this client, labeled as the client input; do not paraphrase it or claim the host independently verified the HTTP body. On recovery, show the original prompt only when it is known from the original invocation; if it is unavailable and the user asks, say so. Keep operation IDs, payment IDs and file metadata out of the default success message, while preserving them for recovery and reporting them when the user asks. Follow the user's requested detail when it differs from this default.

## Setup

On `SERVICE_CREDENTIAL_NOT_FOUND`, explain that this invocation selected credentialed access and no matching API key was found. This error belongs to an explicitly credentialed or saved legacy operation; default anonymous x402 requests do not use that provider. Explain that a service API key is unnecessary for new wallet-paid requests, preserve the original operation, and do not silently switch or retry it.

On `IMAGE_CONFIG_MISSING`, `IMAGE_CONFIG_INVALID`, `IMAGE_SERVICE_URL_INVALID`, `IMAGE_CONFIG_LOCATION_UNAVAILABLE`, stop and tell the user to configure the public service endpoint. Default anonymous wallet payment does not need an API key. Only an explicitly credentialed caller configures a key through KoinCode's trusted service credentials settings. On the user's explicit instruction to configure or change the endpoint, run `python3 <absolute-skill-directory>/scripts/configure_image.py --url <complete-non-secret-endpoint>`; it only stores the URL, never the key, and sends no request. The origin and `/v1/images/generations` path must match the host credential. If no endpoint was supplied, ask the user for the non-secret URL rather than searching or guessing. Explicit `--url` on the generation script is supported for a user-specified endpoint. Saving a URL does not validate access or approve payment. If an anonymous request receives 401/403 or the service is disabled, report that actual server state; do not ask for an API key as a substitute for enabling the intended anonymous service.

Keep HTTP completion, business success and chain settlement separate. Query/reconcile the original payment when needed; an image or transaction hash alone does not establish settlement. An explicit independent user request may proceed while an earlier operation remains unknown; it does not resolve that operation and may use service rights, quota, or require a new payment. Do not silently repeat an unknown operation, replace its payment or claim a new request is free. The wallet's normal payment authorization and limits still apply. If the host lacks the required private connection or durable state, stop and report that capability gap.

Report a payment amount or confirmed settlement only when supplied by the host's trusted payment result for this specific invocation. A quote is not proof of payment, a prior purchase is not a new charge, and absence of `paymentId` does not prove the price is zero. If the amount or payment status cannot be established, report it as unknown; never infer it from the image, the model's text, or merchant headers. Let the host display its own payment status and do not claim that a particular host provides a payment card unless it actually does.

When a host tool reports missing client registration, unavailable wallet service, authentication failure, missing credential configuration or `PAYMENTS_DISABLED`, stop and show the actual setup error and the host's trusted configuration entry. Do not search local wallet files, Keychain data, application source, application executables or unrelated configuration to work around it. A canonical-path input error permits resolving this Skill's own path once, before any business request. On `PAYMENT_QUOTE_DISPLAY_UNAVAILABLE`, stop and tell the user that the host could not confirm display of the payment quote; preserve the returned operation and payment IDs and report payment state only from trusted wallet evidence. Do not automatically issue a new request, retry payment, search source code, or claim that payment occurred or did not occur from this error alone. The script only closes PAYMENTS_DISABLED or PAYMENT_RECONCILIATION_REQUIRED as failed after the wallet confirms the original unsigned failure and no intent or payment risk. Repeating the same operation or `--recover` never creates a new request. Wait for the user to finish setup; do not create another generation request while waiting.


For an ordinary generation request without an additional user-specified spending ceiling, omit the entire `paymentLimit` property. Existing wallet authorizations and wallet limits remain authoritative. Never invent `maxAmountAtomic: "0"` as a placeholder or assume zero means unlimited: an explicit zero forbids all positive payments. If an explicit ceiling rejects a quote, do not increase it or repeat the operation automatically. A separate explicit user request is required for a new independent operation.
