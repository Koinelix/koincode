# Wallet and caller compatibility

This independent Skill owns merchant HTTP, business persistence and image processing. The general wallet validates the submitted x402 v2 exact challenge, enforces client scope, grants and budgets, signs the supported authorization and independently reconciles settlement. Because the Skill sends the HTTP request itself, validating the challenge does not independently establish its merchant origin or prove the actual HTTP request matches the submitted digest. The current wallet implementation supports Base Sepolia test USDC; do not assume other networks or mainnet.

The Python entry is `scripts/generate_image.py`. Its private JSON client speaks protocol version 1 through inherited fd 3. A compatible caller supplies context (private state/output directories and stable task identity), the general payment methods. The default anonymous x402 image request needs no service credential provider; only explicitly credentialed compatibility requests use one. On KoinCode, the official generic `wallet_run_client` host tool supplies that connection. No merchant-specific Agent loader, wallet setting or wallet image decoder is required. Another host can implement the same caller environment or adapt the thin transport without changing the image API or wallet.

The wallet's authenticated public local protocol is available to any registered client, including another application's MCP server. An MCP server keeps payment material inside its HTTP implementation rather than returning it to its model. Other applications need no KoinCode script launcher. The optional `credential.read` and `context` methods are host facilities, not wallet methods; another client may use its own secure credential source.

The script persists a business key and exact request before HTTP. A successful response is saved before bounded standard-library image validation and file publication. A saved response can be re-delivered after a script/application restart under the same installed Skill path and session; this does not issue merchant HTTP or call the wallet. If no response was retained, the script reports unknown/pending and never silently purchases again. The service cannot recover a discarded successful image.

Each initial or paid HTTP phase has a 20-minute socket timeout. The host bounds the complete caller invocation to 50 minutes and terminates the caller process group on cancellation. This is an operational bound, not an OS sandbox. Wallet quote/signing freshness remains short-lived; waiting for a generated image does not extend signing authority. The local desktop, service and Base Sepolia paid-image path was exercised on 2026-10-29. Production distribution and mainnet are outside that acceptance.

After a paid response, the caller may pass the bounded PAYMENT-RESPONSE transaction as an optional transactionHash to reconcile_payment. This is only a lookup hint: the wallet verifies the original authorization and token transfer on chain before accounting. Missing hints or RPC/older-wallet failures preserve financial uncertainty and never trigger another purchase or discard a saved image.

The [reference host adapter](reference-host.md) exercises the public payment-v1 contract independently of KoinCode. It is POSIX-only; Windows requires an ACL-authenticated pipe adapter and fails explicitly here. Access and API version are frozen in durable request state. Historical records remain credentialed legacy records; switching mode for the same request is rejected.
